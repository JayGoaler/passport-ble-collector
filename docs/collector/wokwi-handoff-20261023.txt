目标设备第一步

  使用归档外附带的同名校验工具，或源项目 tools/verify_collector_handoff.py。
  校验通过后加 --extract-to <尚不存在的新目录> 恢复；该工具会先校验完整清单。

Wokwi 环境
  ESP-IDF 5.5.3；源 Mac 使用隔离工具链与 Wokwi CLI v0.29.0。
  源 Mac 可用 python tools/wokwi.py build / lint / smoke / flow；参数见 sim/wokwi/README.txt。
  WOKWI_CLI_TOKEN 在目标机器单独设置，或 --token-file 指向目标机本地文件；
  不把 Token 复制进源码、归档或日志。CLI 只发送仿真镜像和合成数据。
  macOS 的 passport 构建入口不是 Windows 安装脚本；Windows 原生构建环境
  仍按既有 windows-native-handoff.txt 核对，当前未在 Windows 运行 Wokwi。

预构建仿真材料
  归档内 evidence/logs/simulation-only/ 保存独立 build/wokwi 文件及清单，
  对应运行结果见最终验收报告。恢复到解包后的 source/build/wokwi/：
  1. 将 wokwi-sdkconfig.txt 复制并重命名为 sdkconfig。打包器排除所有同名
     sdkconfig，因此归档使用该别名；未重命名将无法通过仿真产物摘要校验。
  2. 其余文件保持原有名称和相对子路径，包括 bootloader/ 和 partition_table/。
  3. 从 source/ 运行 tools/wokwi.py smoke 或 flow，使用目标机 --cli、
     --token-file 和新的 --output。工具核对 simulation-manifest.json 中的源码及
     产物 SHA-256；摘要不匹配时先查明原因，再按目标环境重新 build，不跳过校验。
  跨机 CLI、权限与账户配额须在目标机实际验证；源 Mac 的通过不等于笔记本通过。

场景与计时
  smoke 保留启动、空设备、诊断、菜单和 USB 窗口五张图（01 至 05）。
  flow 先配置，再覆盖采集、切换设备、暂停和恢复，共八张图（01、05 至 11）；
  不要求 flow 再生成 02 至 04，空状态由 smoke 覆盖。是否通过以最终报告为准。
  心跳周期仍是 30 秒，没有缩短；flow 等待第二次心跳并核对控制器 ACK。
  仿真使用 80 MHz CPU、100 Hz RTOS tick，正常固件使用 160 MHz、1000 Hz。
  固定合成 USB 配置和从 2026-10-23 开始的模拟 UTC 不证明真实联网或校时。
  本轮不依赖后端，不包含 Wokwi CLI Token，也未进行目标笔记本验证或刷机。
