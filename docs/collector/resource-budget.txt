资源预算与实现边界
日期：2026-10-23；目标 ESP32-C3，8 MB Flash，无 PSRAM，ESP-IDF v5.5.3。

一、按任务书允许的起始策略调整

首轮 32 聚合槽、64 事件、32 KiB 正文和 SDK 默认无线配置，链接器报告
DRAM 使用 298096 B、余 23200 B。不能仅凭链接成功认为它能同时运行
Wi-Fi、BLE、LVGL 和 TLS。因此采用以下有界配置：

- 同时聚合 16 个地址，精确 RSSI 直方图中位数；队列 32 条、TTL 300 秒。
  col_store 的主机 sizeof 为 26392 B，编译检查仍要求小于等于 64 KiB。
- 满表后首个溢出地址获得下一窗口的保留位置，最多等待 250 ms；对所有未准入
  样本计数。该策略减少固定顺序广播源饥饿，不保证密集环境全覆盖。
- 样本任务队列 16 条，满时回调不阻塞并计数；不缓存原始广播报文。
- 正文缓冲 8192 B、响应 4096 B；单批不超过 32 条和协议 32 KiB。
  实际字段装不下就停止在完整事件边界，剩余事件留待下一批；单条最大字段可装下。
- 凭据任务和 HTTP 任务串行，复用同一 job 内的正文/凭据空间。
- UI 保留独立 24 KiB 静态池。真实 LVGL 主机测试中 12/16 KiB 初始化失败，
  因此未采用；24 KiB 通过全部页面及 64 次长字段翻页，峰值约 14.6 KB。
  主机是 64 位，不能将该峰值当作 C3 的真实占用。
- 显示单 DMA 缓冲从 40 行改为 20 行：240×20×2=9600 B，避免双缓冲。

二、无线与运行期上限

- NimBLE host 与 controller 都只启用扫描；不启用连接、广播、配对和测试模式。
- BLE controller 仅 1 个活动；MSYS1/2 各 4，ACL 4，高优先级事件 8，广播事件 8。
- Wi-Fi static RX 4、dynamic RX/TX 各 8、RX BA 4；关闭 Wi-Fi IRAM/RX IRAM 加速。
- FreeRTOS 仅搬移 SDK 允许的非 ISR 函数到 Flash，不更改 ISR 放置规则。
- mbedTLS 按实际需要动态分配 record 缓冲，接收 16384 B、发送 4096 B；
  不通过缩小入站 record 或跳过 CA/主机名验证来节省内存。
- controller 栈 6144 B，network/USB 各 8192 B，BLE 使用 SDK 配置，UI worker 4096 B；
  另有 LVGL port、Wi-Fi、TCP/IP、event/timer 等 SDK 任务。栈数值是分配预算，
  不是实机已验证余量。METRICS 每 30 秒记录各应用任务余量及 heap/minimum/largest。

三、解释内存证据

最终链接器的 DRAM 使用/余量见 acceptance-20261023.txt 和 evidence 的 full-gate.log。
size 不是启动 heap 报告；C3 的运行期内存还受 ROM/ECO 保留区和启动栈回收影响，
不得把链接脚本之外可能释放的区域计为确定余量。TLS 握手、证书链、无线收发峰值、
碎片和 DMA 连续块必须在目标设备测量。当前只能确认静态预算与有界行为。

后续若增加容量、界面或持久化，先重新记录链接器 size 和上述运行期指标，
再进行 D09/D10。不要为恢复更大的数字删掉限制、关闭测试或弱化 TLS。

四、功能边界

凭据与观测均不写 Flash；断电丢失，D11 加密持久化未实施。
每地址最多保留 4 个 service UUID；未知动态名字字形显示 [?]，不改上传 UTF-8。
服务端 5000 设备、200000 历史事件限制不变，固件无管理清理权限。
异常满载可计数丢弃，不能承诺断网三分钟零丢失或 24 小时无限保存。
